# v0.4 手机扫码优化与验证

## 范围

不加入固定接收模式，不加入声音提示。保留无网络光学传输、桌面单 HTML、移动端离线 PWA 和 iOS 点击分享导出的边界。

实现：二维码附近原分辨率裁剪与快速解码、周期性全画面重定位、位置/码尺寸/断流提示、场景预设、有效新增编码数据速率、压缩感知估时、按原始字节加权进度、页面内暂停续接、前后台恢复、防息屏生命周期、提高清单重复频率。调整发送端显示大小不再重启帧流。

## 验证记录（2026-09-09）

- 166 项单元与模拟链路测试通过（含防息屏释放/恢复测试）；类型检查、桌面单文件与 PWA 构建通过。
- 使用 Playwright 的 390×844 视口，注入 canvas.captureStream 模拟摄像头，但二维码读取使用实际 ZXing WASM Worker，分段存储使用实际浏览器 OPFS。
- 测试图像生成：`node --import tsx tests/mobile-fixtures.ts`。输出只在忽略的 artifacts/mobile 下，不进入发布产物。
- 1280×960 源画面中定位二维码后实际提交裁剪图像；移到原裁剪区域之外后重新定位。缩小到 300 像素码时显示“二维码偏小”。这说明路径有效，不等于手机吞吐提升倍数。
- 在 7% 进度暂停并继续，仍保留 7% 和未完成分段；没有重新建立传输。
- 隐去二维码后显示信号中断，并停止剩余时间估算；恢复图像后继续接收。
- 最终自动下载 10,000 字节文件，与原文件逐字节一致；SHA-256：`1e0d7c1f75b60785a19d26b1335ce40ba353da1154e09905170a9e411da3e3e0`。
- 回归暴露旧 OPFS 下载在立即清理后被取消的问题。改为先读取独立 Blob，再触发下载与清理；同一测试下载成功。读取失败仍走保留检查点路径。
- 移动端无横向溢出，接收时收起初始设置，让取景画面、状态与暂停按钮保持紧凑。

## 后续测量，不在本次冒进调整

- 未进行 iPhone / 华为真机光学测速；反光、自动对焦、滚动快门、热降频和操作系统后台冻结不能用模拟视频替代。
- 喷泉模式在不同丢帧条件下各有优势，保留可选预设，不承诺稳健模式总是更快。
- 分段调度仍保留现有轮播，不盲目缩小轮播窗口；单向传输没有接收完成反馈，重复播放已完成窗口可能拖慢整体速度。
- 发送端二维码生成移入 Worker、运行时自适应并行度等，需结合真机长时间 CPU/温度/有效吞吐采样决定；当前先减少接收端每帧像素工作量，手机默认两个解码 Worker。
- 估时包含编码冗余预算，但不包含轮播等待；超过预算仍需补帧时不会显示已经完成。手机大文件自动下载还受可用内存和浏览器下载策略限制。
