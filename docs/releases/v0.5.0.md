# v0.5.0：多码与跟踪解码实验版

## 功能

- 新增单码 / 双码 / 四码选择，默认单码；双码横排、四码 2×2，每码独立分片和白边。
- 二维码编码移入后台线程，最多预备 3 张画面；显示实际播放 fps。
- 集成 decimen-codec v0.2.0（dc2b8c5）跟踪采样，失败在同帧重新定位，再回退通用 ZXing。
- 每 1.5 秒全画面搜索；仅协议/CRC 验证成功的二维码位置参与裁剪和跟踪，不恢复跳动蓝框。
- 自动估算 1–4 个解码线程，每三秒最多调整一个；支持手动线程数和兼容解码 A/B 对比。
- 修正窄屏和旋转后多码被裁切；保留 iOS 点击导出、取消/失败保留数据的流程。
- 组合项目采用 AGPL-3.0-or-later，保留旧 MIT 声明，页面提供源码入口和完整许可。

## 验证（2026-10-15）

- 类型检查、179 项自动测试、单文件与 PWA 构建通过。
- 真实 WASM 测试：1/2/4 码解码、每码序列独立、完整文件重组、移动后同帧重新定位、
  2331/2953 字节高密度四码 full/tracked 逐字节一致。
- Chromium 浏览器：1/2/4 码跟踪模式、4 码兼容模式接收并自动下载；下载 SHA-256 与原文件一致。
- 断网浏览器：PWA 缓存后离线重载并接收双码；单文件页面断网后从内嵌 WASM 接收双码，均下载并清理成功。
- file:// 单文件双码发送通过，目标 30 fps 实测约 30 fps（桌面合成小文件）。
- 390×844、844×390、1280×900 布局检查；四码未超出容器。

合成桌面 CPU 微基准（3 像素/module、四码、同图 30 次均值，不含摄像头、渲染、文件还原）：

| 每码字节数 | 重新定位 | 跟踪解码 |
|---|---:|---:|
| 2331 | 6.34 ms | 2.46 ms |
| 2953 | 7.56 ms | 3.38 ms |

复现：`node --import tsx --test tests/multicode.test.ts`。测试输出时间依机器和负载变化，
不以固定倍速作为通过条件。光学信道、手机温度、对焦与摩尔纹未被上述合成测试覆盖。
尚未在真实 iPhone / 华为摄像头上测定吞吐，不承诺 2×/4× 或 100 KB/s。

## 试用

发送端先选双码，接收端保持「跟踪优化」和「自动线程」，把全部二维码及白边收入镜头。
若识别稳定再试四码；若更慢，先降每码字节数或退回单码。对比「有效速率」而不是目标 fps。
PWA 更新时先联网打开，确认页脚 v0.5.0，再离线使用。没有新增固定接收模式或声音提示。
