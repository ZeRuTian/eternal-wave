# Eternal Wave 动态二维码文件传输

用屏幕和摄像头传输文件，不经过网络。发送端把文件编码成不断变化的动态二维码，
接收端用摄像头扫描并还原文件——两台设备之间没有任何网络路径。

- 简体中文单页，发送/接收一体
- 单文件上限 256 MB，按 4 MiB 分段（每段独立压缩、喷泉编码、校验）
- 可选口令加密：PBKDF2-HMAC-SHA-256(600,000 次) + AES-256-GCM，口令不落盘
- 接收端支持中断续传（刷新页面后重选同一目录即可恢复）
- 运行期间零网络请求，不引 CDN、不上传文件、不含遥测
- 派生自 [Decimen Optical Transfer](https://github.com/bashalarmistalt/decimen-optical-transfer)，保留原作者署名。
  v0.5 起集成 AGPL 跟踪解码器，组合项目采用 **AGPL-3.0-or-later**；原 MIT 部分声明保留在 LICENSE-MIT。
  协议仍为独立的 Eternal Wave Protocol v1，与上游不兼容。

## 快速开始（桌面）

1. 复制 `dist/Eternal-Wave.html` 到 U 盘（或任意电脑）。
2. 用 Chrome / Edge 109+（Windows x64、银河麒麟 V10 SP1 x86_64/ARM64、Linux）双击打开。
3. 发送端：点击「发送文件」→ 选择文件 →（可选）输入加密口令 → 屏幕出现动态二维码。
4. 接收端：在另一台设备打开应用 → 点击「接收文件」；桌面选择保存目录，手机自动准备本机存储；然后选择输入源：
   - **摄像头**：两台设备互传（电脑→手机、手机→电脑、电脑→电脑），对准发送端屏幕；
   - **屏幕捕获（同机互传）**：同一台电脑双开两个窗口，在弹出的窗口列表里选中发送端
     窗口即可，无需摄像头、不受摩尔纹/对焦影响，吞吐通常更高。
5. 传输完成后自动校验 SHA-256；校验通过后自动保存到所选目录并清理临时文件。

> 浏览器必须允许使用摄像头/屏幕捕获和选择本地目录；企业安全策略禁用这些权限时无法绕过。

## iPhone / iPad（PWA 预装）

iPhone 不能从本地 HTML 直接调用摄像头，接收端需提前以 PWA 方式安装：

1. 用 Safari 打开 [Eternal Wave 在线安装页](https://zerutian.github.io/eternal-wave/)（不要直接打开 ZIP 或 GitHub 仓库页）。
2. 点击分享按钮 →「添加到主屏幕」；新版 iOS 若显示「作为 Web App 打开」，请保持开启。
3. 从主屏幕首次打开时保持联网，等待页面完整加载后即可完全离线使用（可开启飞行模式验证）。
4. 接收完成并通过 SHA-256 校验后，点击一次「存储到“文件”…」，在 iOS 系统面板选择
   「存储到‘文件’」。这是 WebKit 对文件导出的用户手势要求；导出成功后应用会自动清理
   临时分片，取消或失败则保留检查点，重新打开应用扫描同一发送端即可再次导出。

在线安装页由 [GitHub Pages 工作流](.github/workflows/deploy-pages.yml) 自动构建和更新；也可将
`dist-pwa/` 部署到其他 HTTPS 静态服务器。

## 安卓 / 华为手机

- 推荐通过 HTTPS 打开在线安装页，并用 Chrome、Edge 或新版华为浏览器使用；首次联网加载完成后，
  可添加到主屏幕并离线运行。
- 接收端会按浏览器能力直接启用 OPFS 本机存储，不再依赖浏览器是否报告“独立 PWA”模式，
  因此 EMUI、HarmonyOS 上未显示安装入口时也可直接在浏览器页面中接收。
- 安卓接收完成后仍自动触发下载并清理临时分片；请在首次使用时允许浏览器下载文件。
- 自动下载前会把 OPFS 文件读成独立数据，避免清理临时文件使下载失效；这一步需要额外内存，
  内存不足或读取失败会保留临时文件。浏览器没有网页可用的“下载已落盘”确认接口，请检查下载列表。
- 需要摄像头、OPFS 和 WebAssembly 支持；过旧的系统 WebView、微信内置浏览器等兼容性不保证。

## 传输设置

- **帧率 (fps)**：10–60，默认 30。接收端解码吃力时降低。
- **每帧字节数**：500–2953，默认 2331。画面噪点多时降低到 1465。
- **纠错级别**：默认 L（喷泉码已处理丢帧，无需高纠错）。
- **加密口令**：发送端设置后，接收端扫描时会被要求输入同一口令。

### 手机扫码体验（v0.4）

- 仅保留 **手机扫码**（30 fps、2331 字节、稳健喷泉码）和 **屏幕捕获**
  （60 fps、2953 字节、快速喷泉码）两个预设，以及 **自定义**。
  选择自定义会展开参数面板；手动修改帧率、每帧字节数、纠错级别或传输模式会自动切换为自定义。
  难以起扫时可自定义为 24 fps、1465 字节；高帧率不一定有更高有效速度。
- 保持二维码清晰、白边完整即可开始。淡色虚线只是静止的取景参考，不必精确对齐；
  不显示跳动的检测框，也不根据失败候选位置判断远近。可以实时调整发送端二维码显示尺寸，不重启传输。
- 只有通过协议及 CRC 校验的数据帧位置才用于原分辨率区域裁剪；连续三次失败立即恢复全画面搜索，
  同时保留定期全画面搜索，避免误锁局部图案。接收中显示真实数据状态与断流提示。
- 显示最近几秒新增编码数据的速率（不计重复帧），预计时间按未收齐编码量计算；
  信号中断或没有新数据时停止倒计时。估时不包含分段轮播等待，不是完成承诺。
- **暂停接收 / 继续接收**保留当前页面尚未完成分段的内存进度；切到后台自动暂停，
  回到前台尝试恢复摄像头与防息屏。浏览器不支持或拒绝防息屏时不能保证屏幕常亮。
  关闭或刷新页面仅恢复已完成分段，且发送端必须仍是同一传输会话。
- 清单每 24 个数据帧重发一次，缩短中途加入时等待文件信息的时间。

此版本不包含固定接收模式或声音提示。纯光学传输仍受屏幕刷新率、摄像头、反光、对焦和码密度影响，
没有物理设备实测前不承诺倍速提升；大文件仍可能需要较长时间。

## v0.5 实验提速

- 「二维码布局」可选单码、双码、四码。每个码发送同一文件的不同分片，接收端自动识别，无需设置码数。
  双码横排，四码 2×2；每个码均保留独立白边。默认仍为单码。
- 二维码编码移到后台线程，发送队列最多预备 3 张画面；显示实际播放 fps，避免把目标帧率当成实际吞吐。
- 接收默认使用 decimen-codec 跟踪解码：用上次校验有效的位置直接采样，失败在同一张图上重新定位，
  再失败回退通用 ZXing。每 1.5 秒重新搜索全画面，避免遗漏新码；失锁时恢复搜索。
- 「接收设置 → 解码方式 → 兼容模式」可以进行同条件 A/B 对比；默认按实际耗时调整 1–4 个解码线程，
  每三秒最多增减一个，避免频繁切换；也可手动指定线程数。
  「传输详情」显示实际解码方式、码数、处理耗时及繁忙丢帧；解码数/秒可以大于摄像头 fps。
- 先试双码；四码需要屏幕和相机提供足够像素。将所有码与白边一起收入画面，若无法稳定识别，
  降低每码字节数、提高采集分辨率或切回单码。60 fps 需发送屏幕和接收摄像头均能跟上。
- 保留原分辨率 Canvas 采集，不默认采用上游在 iPhone 上曾变慢的 ImageBitmap 路径；
  没有新增跳动检测框、固定支架模式或声音提示。真机收益须实测，不承诺 2×/4× 或 100 KB/s。

## 安全说明

- 加密只保护二维码光学传输内容；接收后保存到本地的文件由操作系统权限保护。
- 口令遗失不可恢复；口令不写入二维码、检查点或日志。
- 接收端对所有帧头做严格上限校验（长度、段数、块数、压缩炸弹等），
  恶意构造的二维码无法触发大额内存分配。

## 已知限制

- 浏览器策略禁止摄像头/目录选择时无法使用（网页无法绕过）。
- iOS WebKit 不允许接收完成回调直接保存 Blob，因此 iPhone/iPad 最终导出需要一次用户点击；
  安卓和桌面端不需要这一步。
- 第一版一次只传一个文件；不支持目录、批量文件与文本片段。
- 发送端重启后视为新传输，接收端续传仅针对同一仍在播放的发送会话。
